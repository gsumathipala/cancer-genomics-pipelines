Assay / panel

Pick the kit and the run is configured for its chemistry in one step: interval padding, the allele-fraction and depth floors, whether duplicate marking is meaningful for this library, the UMI layout, and which report statistics the panel is large enough to support. Every one of those is silent when it is wrong — a run with duplicate marking left on for an amplicon panel finishes normally and calls from a fraction of its real depth. Anything you fill in yourself below still wins over the profile. What each profile sets.

The panel BED fills both target intervals and coverage BED below, which are the same file in all but unusual laboratories — filling only one of them is how a run ends up either calling genome-wide or making no coverage statement at all. No profile ships a BED: vendor BEDs are licensed, version-specific content that has to come from your kit. If its contigs are named the Ensembl way (1, MT) the run detects that and calls over a renamed copy rather than failing.

Resources

BQSR runs only when dbSNP or known indels are supplied.

The coverage BED is checked against the alignments before the clinical report is written, and every region that fails to reach the depth threshold is named in a per-sample HTML report you can open from the run page while the run is still going. It answers the one question a VCF cannot: a region nobody sequenced and a region that is wild type both appear as no variant, and only this tells them apart. Leave it blank and the run proceeds without the step — it simply makes no coverage statement.

For a capture panel or exome, give the vendor’s target BED. Without it Mutect2 walks the whole genome and calls on off-target reads — tens of thousands of spurious PASS calls on a typical panel. Padding of 50–100 bp is usual; a minimum depth of around 20 tags thin calls, which GATK never does on its own.

Clear the MSI models path to omit MSI scoring. It is the only route to an MSI answer on a targeted panel — PCGR restricts its own MSI prediction to WGS/WES tumour–normal runs.

The contamination resource is a common-SNP VCF such as small_exac_common_3.hg38.vcf.gz. Without it the run cannot estimate cross-sample contamination, so filtering assumes a fraction of zero instead of measuring it — which matters most for tumour-only runs.

Clinical report (PCGR)

Depth and allele fraction are always lifted from FORMAT into INFO tags before the report is built — without them PCGR has nothing to filter on and the reported TMB would be computed over unfiltered calls, so this is not offered as a choice.

The tumour site steers actionability: the same variant can be predictive in one tissue and only oncogenic in another, so naming the site changes which evidence PCGR treats as on-label. Leaving it Any / not specified is a legitimate choice — the report then covers every tier without asserting a tissue.

PCGR runs after the pipeline, in its own conda environment — it cannot run inside the pipeline's. If the webapp cannot find that environment, set PCGR_PYTHON to its interpreter before starting the server.

The run is not finished until PCGR is. The run page stays on reporting for the hour or so it takes, keeps the Cancel button, and only offers the report once there is a report to offer.
